# ひぐらし公式サイト：更新のしかた

HTMLに直接書く方式です。ライブも楽曲も外部データの取得は行いません。
共有ヘッダーだけ、GitHub Pages標準のJekyllで各ページへ組み込みます。

## GitHubへのアップロード

1. ZIPを解凍し、中のHTML・CSS・`_config.yml`・`assets`フォルダーを、リポジトリの一番上へ上書きします。ZIP自体や外側のフォルダーはアップしません。
2. `live-settings.js`がリポジトリに残っている場合は削除します。今回受け取ったソースにはありませんでした。
3. Pagesの設定は「Deploy from a branch」→使用ブランチ→「/ (root)」です。すでにこの設定なら変更不要です。
4. `.nojekyll`がある場合は削除します。共通ヘッダーの組み込みにJekyllを使うためです。
5. 公開処理が成功した後、PC・スマートフォンで表示を確認してください。

`README.md`は説明書です。アップしても構いませんが、サイト公開には必須ではありません。

## どのファイルを編集するか

| ファイル | 内容 |
| --- | --- |
| `index.html` | トップの写真・紹介映像・紹介文・作品一覧・ページへの案内 |
| `live.html` | ライブ予定・時間・料金・予約ボタン |
| `booking.html` | 出演依頼の入力欄とメール下書き・コピー |
| `stories.html` | 楽曲の物語 |
| `header.html` | 全ページ共通のロゴ・SNS・ページ移動リンク |
| `shared-style.css` | 全ページ共通の色・文字・ヘッダーの見た目 |
| `_config.yml` | GitHub Pagesの公開設定。普段は触らなくてOK |
| `assets` | 写真・ジャケット・手書き文字の元画像・動画 |

ページだけに使うCSSとJavaScriptは、そのHTML内に残しています。新しいライブラリや管理システムはありません。

## ライブの追加・変更・削除

`live.html`の「1公演ここから」から「1公演ここまで」をコピーして追加します。

- 年月日、画面に出る日付、`datetime`の日付をそろえる。
- 会場名、開場・開演時刻、料金、予約URL、ボタン名を書き換える。
- 時刻の`datetime`は`2026-10-24T13:10:00+09:00`の形。`+09:00`は日本時間です。
- 終了した公演は、そのブロックを手動で削除する。
- 公演がなくなったら、記事の代わりに`<p>次のライブは、決まり次第お知らせします。</p>`と書いておけます。

日付による自動削除、スプレッドシート連携、データファイルは使いません。

## 曲の追加

`index.html`の`release-list`内で、`<article class="release-card">`から対応する`</article>`までをコピーします。

曲名、日付（`datetime`と表示日付の両方）、ジャケット画像のパスと説明、配信URLを変更してください。配信URLはジャケットと「音楽を聴く」の2か所あります。

物語がある曲だけ`story-link`のリンクを付けます。物語がない曲は「灯り」のブロックを参考にしてください。

今回は、普段のHTML編集と同じ手順で追加できることを優先し、`_data/releases.yml`への分離はしていません。

## 物語の追加

`stories.html`の`<article class="story" ...>`を丸ごとコピーし、本文と曲の配信URLを書き換えます。

- `id`を重複しない名前にする（例：`new-song`）。
- 見出しの`id`（例：`title-new-song`）と記事の`aria-labelledby`を一致させる。
- 上のナビに`<a href="#new-song">曲名</a>`を追加する。
- トップの「物語を読む」も`stories.html#new-song`へつなぐ。

URLの`#`で物語を選び、CSSだけで表示を切り替えます。指定がない場合は月下美人です。既存の物語本文には変更を加えていません。

## 出演依頼の動作

入力内容から`mailto:`でメールアプリの下書きを開きます。サイトから送信や保存は行いません。

宛先は`sonohigurashi45@gmail.com`です。宛先と依頼文をコピーする機能も残しています。
空欄の主催者名・担当者名・出演希望日は本文に出しません。内容も空欄なら、相談用の文章を表示します。

## 確認したこと・未検証のこと

受領した`higurashi-web-main.zip`を基準に、以下を確認しました。

- HTMLのタグの対応、重複ID、ローカルファイル・ページ内リンク・SVG参照先を検査。
- 全画像・動画14点が元データとバイト単位で一致。
- 4つの物語の記事全体が元のHTMLと一致。
- JavaScriptの構文を検査。
- 空欄・一部入力・全項目入力の依頼文、改行や記号を含むメールURL、コピー処理をテスト。
- 3秒後のスクロール、手動操作5種類によるキャンセル、ハッシュ・既存スクロール・動きを抑える設定による抑止をテスト。
- 紹介文の表示、動画の再生・停止、音声切り替え、ヘッダー配色の処理をテスト。
- スマートフォン向けのCSS指定（フォーム1列・ヘッダー・作品・公演・写真）をコード上で確認。

未検証：

- Jekyll実ビルド：この作業環境にRuby/Jekyllがなく実行できませんでした。今回使う既存のfront matter・include・条件式は検証用に展開し、参照を確認しています。実ビルドの代替にはなりません。
- PC・スマートフォンの実ブラウザー表示：実行可能なブラウザーがなく、実画面での確認はできていません。CSSの描画や`:has()`による物語切り替えは、公開後に現在のChrome/Safari等で確認してください。
- 実端末の動画自動再生、メールアプリの起動、クリップボード権限：端末側の制約を含む動作は未検証です。上記のJavaScriptテストはブラウザーAPIを置き換えた処理単位の検証です。
- 外部サイトのリンク先が現在申し込み可能かどうかは未検証です。予約URL・SNS・配信URLは受領した内容を維持しています。

GitHubへのアップロードや公開サイトの変更は行っていません。

## 設計上の整理

- 更新する内容は、そのページのHTMLに直接記述します。設定用データファイルは増やしていません。
- 共通ヘッダーと共通CSSだけを別ファイルにしています。
- 動画はplay()に必要な読み込みを任せ、読み込み状態を自前で管理しません。
- 自動スクロールはタイマー1つです。操作時と移動時に同じ終了処理でイベントを外します。
- 物語はURLのハッシュとCSSで切り替えます。
- メール下書きとコピーは、同じ依頼文作成関数を使います。空の段落だけ取り除きます。
- 表示・非表示、操作のキャンセル、ブラウザーが再生やコピーを拒否した場合など、機能に必要な判定は残しています。
